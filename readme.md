В проекте реализована кастомная система доступов на основе ролей. Вместо встроенных инструментов Django, доступ разграничивается на уровне трех сущностей: Роль, Ресур , Действие

Роль (access_control_role) - Справочник ролей в система, у меня "Admin" and "Manager"
Ресурс (access_control_resource) - Системные объекты доступ к которым нужно разграничить, у меня "invoices" и "analytics"
Действие (access_control_action) - Действия, которые можно совершить над ресурсом, у меня, "read", "create", "update", "delete"

В фиксированном файле intital_data.json уже прописаны роли, ресурсы и действия описанные сверху. Также новые ограничения можно добавлять через эндпоинт:
http://127.0.0.1:8000/api/rules/
с правами и токеном администратора и с телом:
{
    "role": id_role,
    "resource": id_resource,
    "action": id_action
}

Также через эндпоинт:
http://127.0.0.1:8000/api/rules/"id_rule"/
с такими же требованиями как для добавления, можно изменять определенные поля правил, при этом сэт роли, ресурса и действия должны быть уникальными

Нынешняя матрица прав "из коробки" выглядит так
|Роль|Ресурс|Действие|Разрешено|
|---|---|---|---|
|Мененджэр|Инвойс|read|true|
|Мененджэр|Инвойс|create|true|
|Админ|Любой ресурс|Любое действие|Разрешено|

Все эндпоинты кроме регистрации и логина защищены аутентификацией токенами.
